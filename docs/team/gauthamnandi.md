# Gautham - Project Portfolio Page

## Overview

### Project: MishMash

MishMash is a Java command-line meal-prep planner. Users can manage recipes, generate meal plans and grocery lists, and track nutrition against their targets.

### Enhancements implemented

- **Meal-plan generation (`generate-plan`).** Builds a plan of one to seven days, each with three distinct recipes, either at random or from optional calorie and macronutrient targets. This turns the recipe book into a usable plan. Each day must be within 15% of every supplied target. The main challenge was keeping generation fast as the recipe book grows. The generator checks every three-recipe combination for up to 5,000 combinations (about 32 recipes) and otherwise samples 5,000 at random, so the work stays bounded and small books never miss a valid day. Randomness is injected, so tests use a seeded generator and get repeatable plans. I also added the parser, the request, plan and day models, and the first version of `ActiveMealPlan`. Evidence: [#24](https://github.com/AY2627S1-CS2113-W13-4/tp/pull/24), user story [#5](https://github.com/AY2627S1-CS2113-W13-4/tp/issues/5).
- **Meal recording (`record-meal`, `view-meals`).** Lets users log the meals they actually ate and see each meal's calories and macros with running totals, separately from the plan of meals they intend to eat. `MealLog` keeps the immutable `Recipe` rather than its index, so recorded meals keep their nutrition after `edit-recipe` or `delete-recipe`. Totals are computed from the log on demand with `long` arithmetic, so there is no second copy to drift out of step. `ApplicationState` holds the log and `Parser` passes it to the commands, which left the `Command` interface unchanged. Evidence: [#82](https://github.com/AY2627S1-CS2113-W13-4/tp/pull/82), closing [#43](https://github.com/AY2627S1-CS2113-W13-4/tp/issues/43) and [#44](https://github.com/AY2627S1-CS2113-W13-4/tp/issues/44).
- **Plan failure advice.** When generation fails, `PlanFailureAdvisor` tells users the cause (diet filters, too few recipes, or unreachable or conflicting targets) and what to try next, instead of leaving them to guess. It runs only after a failure, so it stays separate from the generator's selection rules. The design challenge was proving a target impossible cheaply: comparing the three lowest and three highest values for each nutrient shows that no combination can reach it, without searching again. Evidence: [#120](https://github.com/AY2627S1-CS2113-W13-4/tp/pull/120), for issue [#59](https://github.com/AY2627S1-CS2113-W13-4/tp/issues/59).
- **Meal history and correction (`edit-meal`, `delete-meal`).** Recorded meals gained optional dates and servings, `view-meals` can show one date, and users can fix mistakes in the log. Totals are recalculated from the log, so they stay accurate after a correction. `MealLookup` gives every meal-number command the same errors, each showing the calling command's format. Evidence: [#120](https://github.com/AY2627S1-CS2113-W13-4/tp/pull/120), for issues [#62](https://github.com/AY2627S1-CS2113-W13-4/tp/issues/62) and [#63](https://github.com/AY2627S1-CS2113-W13-4/tp/issues/63).
- **Awaiting merge: larger plan search.** My branch raises the search limit to 1,000,000 combinations (about 180 recipes) and keeps at most 5,000 matches, using reservoir sampling so that every match is equally likely to be kept.

### Testing

[#82](https://github.com/AY2627S1-CS2113-W13-4/tp/pull/82) adds 66 JUnit test methods in five classes (`MealLogTest`, `MealLogViewerTest`, `RecordMealCommandTest`, `ViewMealsCommandTest`, `ParserRecordMealTest`), plus console-workflow tests in `MishMashTest`. They cover totals beyond the `int` range, exact output, every invalid index, the empty log and empty recipe book, recipes edited or deleted after recording, and failed commands leaving the log unchanged. [#24](https://github.com/AY2627S1-CS2113-W13-4/tp/pull/24) adds eight test classes for generation, including seeded-random plans and parser and target validation. [#120](https://github.com/AY2627S1-CS2113-W13-4/tp/pull/120) adds `PlanFailureAdvisorTest`, `MealCorrectionCommandsTest`, `MealEntryTest` and `MealEntryParserTest`, about 50 test methods in all. [#137](https://github.com/AY2627S1-CS2113-W13-4/tp/pull/137) covers the remaining `ActiveMealPlan` and `DeleteMealCommand` paths assigned to me in [#133](https://github.com/AY2627S1-CS2113-W13-4/tp/issues/133).
